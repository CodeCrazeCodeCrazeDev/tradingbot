# ADR 004: Transition to Shared-Log Consensus Architecture (LogAct)

## Status
Proposed

## Context
AlphaAlgo V4 uses a `UnifiedDecisionBus` for inter-agent communication. While centralized, it lacks transactional reliability, exact replayability, and strong consistency across restarts or failures. Research in *LogAct* (Balakrishnan et al. 2026) demonstrates that deconstructing agents into state machines playing a shared log provides superior reliability and enables decoupled, pluggable verification (voters).

## Decision
We will replace the `UnifiedDecisionBus` with a **LogAct Shared-Log Backbone**.
1. All agent actions (intents) must be written to the log before execution.
2. The log is the single source of truth for the system state.
3. Pluggable voters (Verification Swarm) must approve log entries before they are committed as "executable".

## Consequences
*   **Pros**: Guaranteed recovery; perfect audit trails; deterministic replay; decoupled safety checking.
*   **Cons**: Increased latency for log-write/vote cycles; higher storage requirements for long-horizon logs.
*   **Mitigation**: Implement "Log Compaction" using HIPIF-style Information Folding to summarize old log segments into "Checkpoints".

# ADR 005: Integration of Quantum Knowledge Graphs (QKG)

## Status
Proposed

## Context
Market "facts" are rarely globally valid. A signal that works in High-Volatility is often noise in Low-Volatility. *Agents-K1* (V4) used a static KG, leading to "Regime Hallucination". *Quantum Knowledge Graph* (Wang et al. 2026) solves this by annotating triplets with context-dependent validity.

## Decision
Upgrade the `KnowledgeBase` to a **Quantum Knowledge Graph (QKG)** architecture.
1. Every triplet $(S, P, O)$ must be stored with a `ContextDescriptor`.
2. Retrieval queries must include the current `MarketContext`.
3. The system will filter evidence based on `f(ContextDescriptor, MarketContext)`.

## Consequences
*   **Pros**: Eliminates regime-drift errors; improves signal-to-noise ratio in trade research.
*   **Cons**: Higher metadata overhead; requires dense context-annotation of all market evidence.

# ADR 006: Metacognitive Hyperagent Core

## Status
Proposed

## Context
Previous self-improvement loops (V4) were external to the agent. *Hyperagents* (Zhang et al. 2026) shows that integrating the "Task" and "Meta" agents into a single editable program allows the system to improve its own *search* for improvements.

## Decision
Redesign the `PersistentCognitiveAgent` (PCA) as a **Hyperagent**.
1. The agent source code will be part of the agent's observable and editable state.
2. The agent will have a `SelfModify` action enabled by a restricted "Evolution Sandbox".

## Consequences
*   **Pros**: Faster adaptation; discovery of non-obvious engineering optimizations.
*   **Cons**: High risk of recursive collapse or "reward hacking" the meta-logic.
*   **Mitigation**: The **Evolution Gate** (RSEA) remains an external, authoritative guard that verifies every meta-modification before it is permanent.
