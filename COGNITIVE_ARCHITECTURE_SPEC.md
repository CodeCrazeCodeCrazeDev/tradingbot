## 2. Comprehensive Answers to the 18 Critical Architectural Questions

### Q1: What exactly is allowed to self-modify?
- **Self-Modification Bounds**: The system is allowed to self-modify localized hyper-parameters (such as learning rates, SAGE graph prune parameters, neural network weights of the ACPE), associative edge weights inside the SAGE memory graph, and specific behavioral adapter weights (LoRAs).
- **Prohibited Areas**: The underlying active inference engine, risk engine trigger logic, and the promotion/falsification logic are strictly **immutable**.

### Q2: What is immutable?
- Core code structures (such as `CognitiveSystemController` execution loops).
- Non-bypassable executable Program Functions (risk guardrails).
- The evaluation and falsification test suites.
- The `ImmutableShield` validator code itself.

### Q3: What is learned?
- Transition probabilities and causal structures of the market (learned inside the Causal World Model).
- Contextual experience and conceptual associations (learned as nodes/edges in SAGE).
- Optimal retrieval schemas (learned via AutoMem's metamemory feedback loop).
- Action priorities (learned by the Adaptive Control Policy Engine).

### Q4: What is merely configured?
- Initial hardware execution bounds (threads, process pools, GPU device mapping).
- Base safety limits (max trade sizing, maximum absolute drawdown limit).
- Initial hyperparameters before the first online optimization loop starts.

### Q5: What can change online?
- SAGE Graph weights ($W_t(e)$) are updated in real-time as trade outcomes are settled.
- Active Inference continuous states and discrete quantized tokens representing regimes.
- Parameter updates generated by the ACPE during real-time learning.

### Q6: What requires offline evaluation?
- Any architectural change (e.g. modifying model architectures, adding new features, or changing SAGE schema versions).
- Structural policy updates that alter code execution patterns.

### Q7: What requires human approval?
- Promotion of structural code variations (challenger implementations) to the production `master` branch.
- Modifying the absolute risk bounds and capital allocation limits of the fund.

### Q8: What can be automatically promoted?
- Soft-parameter updates, SAGE schema index improvements, and calibrated policy hyper-parameters that pass the **Falsification Gate** with Wilcoxon significance $p < 0.01$.

### Q9: How are regressions detected?
- Pairwise comparisons of the Challenger against the Champion on the held-out dataset.
- Continuous live monitoring of VFE, ECE, peak VRAM, and planning latency. Any degradation beyond specified tolerances triggers an immediate regression flag.

### Q10: How is rollback performed?
- The `ArtifactManager` deletes the proposed Challenger weights and automatically reverts the symlink to the previous, cryptographically signed Champion checkpoint.

### Q11: How does the system avoid evaluator gaming?
- By completely decoupling the candidate generation pipeline from the held-out validation and falsification data. The candidate has no read or write visibility over the evaluation datasets.

### Q12: How does it avoid catastrophic forgetting?
- By enforcing **Regularized Training** (using the reference model's KL divergence to constrain updates) and checking against a diverse, comprehensive **Regression Test Suite** covering historical market regimes (back to 2018).

### Q13: How does it avoid repeatedly rediscovering failed ideas?
- The Evolution Layer maintains a permanent **Negative Experience Ledger** containing hashes and signatures of failed hypotheses, rejected candidate code, and regression-inducing parameters.

### Q14: How does it distinguish genuine improvement from statistical noise?
- By requiring that any observed improvement in returns or latency pass a **Wilcoxon Signed-Rank Test** with a one-tailed $p$-value $< 0.01$ and an effect size (Cohen's $d$) exceeding $0.35$.

### Q15: How does it prevent self-reinforcing errors?
- By enforcing an **Evidence-First** policy. Every proposed belief or regime transition must be supported by multi-hop causal paths from the SAGE Graph, preventing the agent from acting on ungrounded hallucinations.

### Q16: How does it preserve reproducibility?
- By utilizing the **Deterministic Replay Framework**, which enforces identical seed alignment across PyTorch, NumPy, and random libraries, guaranteeing that replay backtests match capture logs.

### Q17: How does it prevent research contamination?
- By verifying the SHA-256 hashes of all dataset files before executing any evaluation. Any modification to evaluation files is blocked and logged as an integrity violation.

### Q18: How does it maintain architectural coherence while evolving?
- By enforcing the **One Authoritative Implementation** rule. All capabilities have exactly one canonical owner. Proposed changes can only modify parameters or modular adapters, leaving the overall system topology intact.
