# RSI evaluation contract (operator-owned; no operative thresholds yet)

A candidate is an unproven hypothesis. The proposing process must not write the contract, evaluator, baseline, holdout, risk policy, verifier keys or experiment ledger. This specification describes required fields and acceptance conditions; **no numeric default is authorized for promotion**. Operator signs/version-controls instrument-specific budgets, economic hurdles and risk/cost thresholds after data-quality and cost calibration. Without the operator's contract and independent holdout attestation verdict is `insufficient_evidence`.

## Canonical locked record

Required: `schema_version`, unique `contract_id`, immutable SHA-256 of canonical serialized record, operator identity/signature and trust anchor, freeze timestamp, scope (strategy-parameter allowlist, parameter types/ranges, parent version/hash, protected paths), candidate family ID and maximum trials, max recursion depth/CPU/wall-clock/data and holdout query budgets, data asset IDs/content hashes/coverage/calendar/instrument-universe/survivorship policy, feature availability/label horizon in bars, disjoint chronological train/validation/final holdout boundaries, purge and embargo rules, allowed training/update steps, seeds, common sizing/exposure, realistic observed/bounded cost model (`fee`, spread, slippage, latency, funding, impact/capacity), baseline, metrics with units/directions, confidence method and correction across trials, pre-registered primary net outcome/minimum detectable + economically meaningful effect, sample/effective-sample minima, risk/tail/latency hard limits, transfer/regime/stress inventory and tolerances, complexity preference, verifier policy, expiry, rollback/kill conditions. Contract hash fixed **before proposal**; changing contract creates a new experiment family and cannot re-label prior results.

Verifier returns `schema_version`, contract hash, candidate/baseline/strategy/dataset hashes, experiment/trial ID, exact software version/seed, per-bar evidence hash, test windows used (not protected raw holdout rows), metrics/full deltas/intervals/sample counts/trial-family count, gate decisions/fail reasons, verifier identity/time/expiry/unique nonce and signature. Parse and validate all fields against the locked contract using operator-supplied trust anchor. Locally computed digest only proves byte consistency, not independent custody. Unknown/invalid key, replayed/stale signature, wrong baseline or contract, missing costs/coverage or nonfinite fields must fail closed. No project-local dummy signature is considered real evidence.

## Data and hypothesis protocol

Baseline immutable and hashed. Candidate must include falsifiable prediction, adverse-regression prediction and **one** changed allowed causal factor. Feature timestamp must be strictly available at decision time, fills must occur no earlier than next executable quote/bar, and any train label interval overlapping validation/test is purged. Embargo >= maximum leakage horizon from contract; calibration fitted only on permitted training/calibration data and frozen during scored validation/holdout. Never use final holdout for parameter choice; count queries, rotate externally after exposure and quarantine contaminated sets. Run baseline and candidate with identical data timestamps, sizing, cost model and scenarios; include abstention bars in aligned net returns. Deny unimplemented candidate adapters or unchanged outputs; record every trial, including failures and zero-trade candidates.

## Ordered gates

`schema/provenance/budgets` → `safe mutation and sandbox invariant tests` → `data/causality/cost validity` → `paired train/validation research` → `chronological purged OOS and operator-held holdout` → `time/regime/instrument and stressed cost transfer` → `paired dependence-aware uncertainty/multiplicity` → `economic hurdle` → `hard DD/CVaR/exposure/latency/safety bounds` → `Pareto comparison + full regression vector` → `independent verifier attestation` → `eligible_for_operator_review`. Any failed hard gate = reject; incomplete trusted evidence = insufficient_evidence. Human authorizes subsequent **live-capital** stages separately; no auto deployment, not even paper config mutation, in this milestone.

Current `market_data.db` single-instrument `evaluation/walk_forward.py` result is an observed historical diagnostic, not a sealed holdout or calibrated execution model. The existing `IMPROVEMENT_GOVERNANCE.md` 5% score and p<=0.01 examples are not automatically binding: their assumptions and instruments are unverified; operator must establish operative thresholds in a new signed contract.
